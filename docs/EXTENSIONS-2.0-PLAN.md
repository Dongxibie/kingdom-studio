## Phase 2 · Recipe 组合系统扩展

**现状**：已有 5 套组合方案（Luxury Product Card / AI SaaS Landing / Premium Hero / Portfolio Opening / Dashboard Boot），
组合能加载成员、按成员平均分算推荐指数、点开按第一个成员预览。

**要做的事**
1. 把组合升格为**场景化方案**：每套方案写清「适合什么页面、由哪几步组成、先后顺序为什么这么排」，
   方案详情页把成员按顺序列成一条流程（背景 → 内容 → 交互 → 收尾），而不是一堆并列的模板。
2. 按 spec 的三套命名补齐方案：**Apple Product Hero**（滚动揭示 + 视差 + 模糊过渡 + 缩放聚焦）、
   **Luxury Portfolio**（玻璃卡 + 平滑滚动 + 光标跟随 + 图片揭示）、**AI SaaS Landing**（极光背景 + 浮动光球 + 文字揭示 + 磁吸按钮）。
   成员全部从现有 60 个模板里选，不新增模板。
3. 新手引导的终点改成「给一套方案 + 一屏讲解」：选场景 → 直接落到该场景的方案，再让人逐条看成员。
4. 方案与模板的**运行档位联动**：一套方案的整体档位取成员里最高的那一档，并在方案卡上标出来（避免「一套方案里藏着一个吃 GPU 的效果」）。

**验收**：组合方案接口与单测（成员合法性、档位聚合、分数算法）；浏览器实测「选场景 → 落到方案 → 逐个成员预览」。

## Phase 3 · AI Assistant 增强

**现状**：助手已经能做到「模型优先、失败如实回退」，输出意图 + 推荐模板 + 一套组合方案 + 参数建议，模板 key 全部回库核对。

**要做的事**
1. **意图结构对齐 spec**：让模型输出 `{scene, style, effects[]}` 这层「效果清单」，再由系统把 effects 映射到模板
   （映射表用 Phase 1 的七分类 + 触发方式 + 关键词），做到「模型说效果、系统找实现」。
2. **方案落库**：现在模型给的组合只存在于界面上；改成可以「另存为组合方案」（写入 `motion_recipe`，标记来源为模型建议），
   之后它就和内置方案一样能被引用、能被评分。
3. **候选池联动**：当 effects 里有一项在库里找不到匹配模板时，助手明确说「库里还没有这个效果」，
   并从候选池里列出同类候选（这是 Phase 1 留下的接口）。
4. 模型调用可观测：记录每次调用的耗时、是否回退、回退原因，界面上给出「本次是模型 / 内置检索」的说明（现有能力，补齐统计）。

**验收**：单测覆盖 effects→模板映射与「找不到就明说」；用假应答覆盖模型四种失败；浏览器实测两条路径。

## Phase 4 · Music Performance Agent

**现状**：MIDI / 简谱解析、键位映射、时间线、Demo 回放（WebAudio 合成）都已完成；
Desktop Agent 只有协议文档与派发计划（REST），没有真实输入通道。

**要做的事（安全设计优先）**
1. **演奏计划（ExecutionPlan）**：把按键序列编译成「按下 / 松开」成对、带相对时间的命令流，
   复用既有规则校验（同键未松开不得再按、单次按住 40–2000ms、单键、总数上限），命令流可导出为 JSON / 文本。
2. **三种执行模式**，默认最保守：
   - `Preview`：只模拟，不动系统（默认档）；
   - `Manual`：逐条确认后执行；
   - `Local Performance`：调用本机输入接口连续执行 —— 必须显式开启，且满足三条硬约束：
     **急停随时可用（ESC 立即松开全部按键）**、**只对前台窗口生效**、**执行过程全程可见（不做后台静默执行）**。
3. **安全开关**：本机执行默认关闭，开启需要一次显式确认；执行中界面上常驻「停止」与剩余时间；
   任何异常先松键再报错。
4. **演奏记录与分享页**：曲目、BPM、音符数、使用键位、难度、档位，以及一份可分享的只读页面（静态 HTML，无后端依赖）。

**验收**：执行计划与安全规则的单元测试（含「异常必松键」「未开启开关一律拒绝」）；
本机执行部分**不接真实按键也能测**——把输入通道抽象成接口，测试用假实现覆盖时序与急停；
真实执行仅在你明确开启后手动验证。

## Phase 5 · 部署与作品包装

1. **登录鉴权（JWT）**：登录 / 注册 / Token 刷新 / 前端路由保护。
   `SecurityConfig` 里已经留了 TODO 与骨架（无状态、关闭 CSRF、BCrypt 已就绪），
   要做的是：`/auth/login` 与 `/auth/register` 接口、`JwtAuthenticationFilter`、`anyRequest().authenticated()`、
   401/403 走统一响应体，前端补登录页并把 token 写进 `localStorage`（`request.ts` 里读 token 的逻辑已在，只是没人写入）。
2. **docker-compose 一键起来**：MySQL 8 + Redis + 后端 + 前端四个服务，初始化 SQL 挂成 volume，
   一条 `docker compose up` 就能打开；`.env.example` 补齐所有必需变量。
3. **Demo 模式**：游客只读体验 —— 示例模板、示例音乐、示例组合可见；写操作（采集、转换、执行）在游客态禁用并给出提示。
4. **README 重写**：项目介绍、架构图、Demo 地址与截图、部署步骤、技术亮点（双集合与来源标注、模型优先可回退的助手、
   运行档位、沙箱预览、三级去重、键位映射两套展开）。

**验收**：登录接口的单测与 curl 实测（无 token 401 / 有 token 200）；`docker compose up` 在干净环境跑通；
README 在 GitHub 上第一次打开就能看懂这个项目在做什么。
