# Motion Workbench 2.0 · Phase 4 变更报告（AI Motion Designer）

> 目标：让「帮我设计一个科技公司首页」这句话，产出一份**完整、可落地、可核对的动画设计方案**
> —— 包括理解成什么需求、选了哪套组合、每一步做什么、参数落地多少、为什么这么定。
> 这一版把 Phase 2 的**五轴意图**与 Phase 3 的**组合系统**接在一起，模型只做「选与调」，不做「造」。

---

## 一、这一阶段交付了什么

| # | 交付物 | 说明 |
| --- | --- | --- |
| 1 | **设计服务 `MotionDesignService`** | 需求 → 五轴意图 → 从 30 套组合里挑一套 → 参数落地 → 逐条说明 |

## 二、模型在这里做什么、不做什么

这是这一层最重要的设计。模型的职责被收窄到三件事：

| 能做 | 不能做 |
| --- | --- |
| 在**已有的 30 套组合**里挑一套（给 recipeKey） | 新增步骤、改步骤顺序、造新的组合 |
| 在每一步**参数自己声明的区间内**微调数值 | 使用模板里不存在的参数名，或超出区间 |
| 写一段设计说明，并补一句规则没识别出的场景 / 风格 | 生成代码、写 CSS/JS 片段 |

所以「模型说得好听但东西跑不起来」从根上不会发生：**结构来自组合系统，代码来自模板库**。

**校验是逐项做的，而且会说清楚丢了什么：**

| 情况 | 处理 |
| --- | --- |
| recipeKey 不在现有 30 套里 | 忽略，沿用规则选出的方案，并在说明里写明「模型给的方案 key（xxx）不在现有 30 套组合里」 |
| 参数名不在该模板的参数表里 | 丢弃并统计：「模型给了 N 处不存在或不可用的参数，已忽略」 |
| 参数值超出区间 | 夹到 `min` / `max` 边界（测试钉住） |
| 场景 / 风格不是枚举值 | 丢弃；即使是合法值，也只在**规则没解析出来时**用来补空，不覆盖规则结果 |
| 整段不可用 | 回退到规则设计，`fallbackReason` 写明原因 |

**没有模型时输出结构完全一样**：同一套意图、同一套组合选取规则、同一套参数落地。
界面上只在右上角的来源标签与「回退原因」里区分 —— 不会假装是模型给的。

## 三、参数落地：三层，每一步都留痕

```
模板默认值  →  模型建议（夹到区间内）  →  轻量预算调整  →  最终值 + 原因
```

每个参数在界面上显示为 `默认值 → 建议值`，并附一句原因，例如：

- `星点密度 1 → 0.5（轻量预算：1 → 0.5）`
- `入场时长 2.4 → 1.2（轻量预算：2.4 → 1.2）`
- 模型建议同理：「模型建议：0.9 → 1.4」

**两条刻意的克制**（都被测试钉住）：

1. **数量类参数按整段匹配**：`--m-timeline` 是时长，不会因为含 `line` 被当成行数减半；
   `--m-outline-offset` 同理。中文提示词（数量 / 粒子 / 个数 / 密度）走包含判断。
2. **时长只在参数允许收短时收短**：背景循环这类参数的下限常是 6 秒以上，
   把 18 秒的循环周期压到 6 秒只会让动画变快，并不会更省 —— 所以下限大于 1.2 秒的时长参数不动。

## 五、这一步和「智能推荐」「动效助手」的分工

| 入口 | 给什么 | 用不用模型 |
| --- | --- | --- |
| 顶部搜索栏（助手） | 若干候选模板 + 一套模型建议的组合 | 模型优先，失败回退检索 |
| 智能推荐（Phase 2） | 一句话 → 五轴意图 → Top 5 模板与理由 | 不用，结果可复现 |
| **AI 设计（本阶段）** | 一句话 → **一套完整方案**：组合 + 每步 + 参数 + 说明 | 可选；用与不用输出结构一致 |

三者互补而不是替代：推荐用来「找素材」，设计用来「出一版能评审的方案」，助手用来「边聊边挑」。

## 六、边界

- **模型只选不造**：它不能新增步骤或改顺序，所以方案永远是「已入库模板 + 已定义参数」的组合。
- **`source` 如实标注**：`MODEL` / `RULE` 与 `fallbackReason` 会明确告诉使用者这次是谁设计的。
- **预算调整是保守的**：只动「越多越重」的数量类与入场时长，且必须落在参数自己的区间里；
  背景循环周期这类参数不动，避免把「更快」当成「更省」。
